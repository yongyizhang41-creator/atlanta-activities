# Product interaction ownership

| Capability | Canonical owner | Source of truth | Allowed variants | Verification |
|---|---|---|---|---|
| Select/Listbox | native select in shared Field | English UI | native | browser keyboard |
| Date | lib/time.ts + ReminderDialog | America/New_York, explicit offset | custom date/time fields | DST unit tests |
| Form | components/ui.tsx Field + form handlers | server validation + inline errors | create/edit/auth | E2E |
| Scrollbar | app/globals.css | DESIGN.md | global, stable gutter | browser |
| Toast | components/ui.tsx Notice | role=status/alert | success/error/info | E2E |
| CRUD | lib/api.ts + FastAPI services | API errors and version checks | save/remove/move | API + E2E |
| Dialog | components/ui.tsx Modal (Radix) | accessible focus management | details/conflicts/reminder/delete | browser |

No table selection in this application. Session 401 redirects to login with local return path. Delete account requires explicit permanent-deletion dialog; removing a plan needs no destructive confirmation and cancels its pending reminder. Errors preserve input and provide retry. Filters cancel superseded fetches. Sensitive coordinates remain transient and are not added to URLs.

Activity coverage: API coverage GeoJSON is the source of truth. features/map/coverage.ts owns merged outline, bounds, clipped nearby geometry and center-dependent useful distance limit. Explore owns native range/number controls and clamps both inputs and center changes. Backend events/coverage.py enforces the same limit; existing PostGIS coverage AND distance filters enforce result containment. Green coverage is persistent; cobalt represents the selected covered area. Coverage is a product collection boundary, not a claim of complete event inventory.

Reminder management: one current unsent schedule per Going event. ReminderDialog saves via PUT /reminder; POST collection and PATCH item routes share the same replacement operation under user/event locks. Saving updates the pending record, invalidates other editable legacy schedules and resets retry state. Only the latest saved time may dispatch. Invalid saves preserve the current time. Sent/cancelled history stays server-side but is hidden in the dialog; submitted/uncertain delivery cannot be overwritten or recalled. Eastern-time/DST validation remains. Source: user request 2026-10-23; app/reminders/router.py and delivery.py. This supersedes independent multiple schedules.

Current location: Explore retains the most recently successful browser geolocation in transient page state, separately from the manually chosen search center. ActivityMap renders one labelled teal marker and pans to it after each explicit Locate me action, respecting reduced motion. Manual center selection/filter changes do not move or impersonate the device marker. The always-visible Explore page-intro Locate me action updates the device marker and camera without changing category or week filters; in Nearby mode it also sets the search center. Nearby initializes from the last successful device position or the existing Atlanta default center. The range updates on input; map responses update independently of list requests, and superseded responses are ignored. The single action owns pending state and page-intro status/error feedback. Repeated requests replace the marker; no location history or URL persistence.

Plan expiry: server removes a user's cancelled or confirmed-ended activities from both Maybe and Going on board reads. Worker cleans all users on its regular tick. The open board revalidates every 30 seconds, on focus/visibility return and at the nearest known event end; stale poll responses cannot overwrite newer reloads. Related dialogs close when their plan disappears. Events and sent/submitted delivery history remain; all cancellable reminders are cancelled. Missing end times expire at midnight following the event start date in America/New_York, using calendar-day arithmetic across DST. This removes saved plans without fabricating an event end time.

Theme: the only theme is Day, declared statically on the root HTML element. globals.css owns the retained smoke-blue glass palette; there is no switch, storage preference, subscription, bootstrap script or system color-scheme selection. Auth uses the same fixed smoke-blue glass palette and shared city backdrop, with labelled translucent fields and mint actions. MapLibre uses features/map/cityStyle.ts to recolor the configured vector style while retaining sources, glyphs, geometry/layout, sprites and attribution. Mint activity markers, cyan device marker and green coverage remain distinct. Existing motion, filters and camera behavior are independent of theme.

Explore desktop split: features/explore/PanelDivider.tsx owns the draggable list/map separator above 900px. Pointer capture and Left/Right keys resize both tracks with 280px minimum widths; double-click or Home resets the default 60/40 ratio. Browser-local ratio persists with optional storage. Mobile List/Map presentation is unchanged. ActivityMap observes container size and resizes its canvas without resetting camera or filters.


Motion: components/motion owns spring parameters, reduced-motion policy and control feedback. EventDayGroups owns keyed enter/exit and position-only layout transitions; activity hover never changes document geometry. The sticky map and drag handles are never animated through transforms. Card hover/focus links by activity ID to a separate MapLibre halo source without changing clustering or camera. Ambient city motion is decorative, non-interactive, pauses while hidden and is disabled under reduced motion. Search cancellation/generation rules continue to own data correctness; animation never delays or triggers requests.


Activity map preview: card hover/focus renders a dedicated gold marker and title at the matching map feature’s real coordinates, regardless of clustering. Already visible locations preserve the camera; offscreen locations pan at unchanged zoom to reveal the point. Preview pan honors reduced motion and stops when superseded; completed preview pans do not cancel later manual camera actions. Leaving removes only preview UI and preserves filters/device location. Tooltip uses textContent, never HTML, and ignores pointer events.
